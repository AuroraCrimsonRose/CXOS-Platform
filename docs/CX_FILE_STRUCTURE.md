# CXEX File Structure Specification

Version: 1.0

## Overview

CXEX is the native executable container format used by the CXK ecosystem.

A CXEX file contains:

* Executable metadata
* Section table
* Section data
* Optional relocation information
* Optional dependency information
* Optional cryptographic signature block

The same container is used for:

| Type              | Extension | Description                    |
| ----------------- | --------- | ------------------------------ |
| Boot Executable   | `.xbex`   | Bootloader executable          |
| Kernel Executable | `.xkex`   | Kernel executable              |
| User Executable   | `.xcex`   | User-space compiled executable |

All files begin with the magic value:

```text
CXEX
```

---

# File Layout

```text
+-------------------+
| CXEX Header       |
+-------------------+
| Section Table     |
+-------------------+
| Section Data      |
+-------------------+
| Relocations       | Optional
+-------------------+
| Dependencies      | Optional
+-------------------+
| Signature Block   | Optional
+-------------------+
```

# CXEX Header

Size: 52 bytes

Little-endian.

```c
typedef struct
{
    char     magic[4];            // "CXEX"

    uint16_t type_code;
    uint16_t format_version;

    uint16_t arch_target;
    uint16_t abi_version;

    uint32_t flags;

    uint32_t entry_point;

    uint32_t load_base;

    uint32_t image_min;
    uint32_t image_max;

    uint16_t section_count;
    uint16_t section_offset;

    uint32_t reloc_offset;
    uint32_t signature_offset;
    uint32_t dependency_offset;

    uint32_t phys_base;

    uint8_t  reserved[4];

} CXEX_HEADER;
```

# Type Codes

```c
#define TYPE_BOOT     0x4245   // "BE"  boot domain       (.xbex)
#define TYPE_USER     0x4345   // "CE"  compiled/userspace (.xcex)
#define TYPE_OS       0x4F45   // "OE"  operating system  (.xoex)
#define TYPE_KERNEL   0x4B45   // "KE"  kernel            (.xkex)
```

Each code is the domain letter followed by 'E' for executable, matching the
extension: X + domain + type. See `docs/CX_EXTENSION_SYSTEM.md` for the full
taxonomy. The kernel's copies are `CXEX_TYPE_*` in
`CXK/kernel/lib/format/cxex.h`.

---

# Architecture Codes

```c
#define ARCH_X86_32   1
```

# Header Flags

```c
#define FLAG_EXECUTABLE          (1 << 0)
#define FLAG_RELOCATABLE         (1 << 1)
#define FLAG_SIGNED             (1 << 2)
#define FLAG_KERNEL_PRIV        (1 << 3)
#define FLAG_REQUIRE_ABI_MATCH  (1 << 4)
#define FLAG_REQUIRE_ARCH_MATCH (1 << 5)
```

# Image Fields

## entry_point

Virtual address where execution begins.

## load_base

Preferred load address.

## image_min

Lowest virtual address used by any section.

## image_max

Highest virtual address used by any section.

Image size:

```c
image_size = image_max - image_min;
```

---

# Section Table

Immediately follows the CXEX header.

Offset:

```c
section_offset
```

Entry count:

```c
section_count
```

Entry format:

```c
typedef struct
{
    char     name[8];

    uint32_t file_offset;

    uint32_t virt_addr;

    uint32_t file_size;

    uint32_t mem_size;

    uint32_t flags;

} CXEX_SECTION;
```

Size:

```c
24 bytes
```

per section.

---

# Section Flags

```c
#define SEC_READ    (1 << 0)
#define SEC_WRITE   (1 << 1)
#define SEC_EXEC    (1 << 2)
#define SEC_NOBITS  (1 << 3)
```

---

# Section Loading Rules

## Normal Section

```c
file_size > 0
```

Loader copies bytes from file into memory.

---

## BSS Style Section

```c
mem_size > file_size
```

Loader copies file_size bytes.

Remaining memory:

```c
mem_size - file_size
```

must be zero-filled.

---

## NOBITS Section

```c
SEC_NOBITS
```

No data exists in the file.

Loader allocates:

```c
mem_size
```

bytes and fills with zeros.

# Signature Block

Optional.

Present when:

```c
flags & FLAG_SIGNED
```

Header field:

```c
signature_offset
```

points to block.

Structure:

```c
typedef struct
{
    char     magic[4];          // "CXSG"

    uint16_t sig_algorithm;

    uint16_t hash_algorithm;

    uint8_t  key_fingerprint[32];

    uint16_t signature_length;

    uint8_t  signature[];

} CXSG_BLOCK;
```

# Verification Procedure

1. Read CXEX header.
2. Locate signature block.
3. Read key fingerprint.
4. Locate matching `.xkpk`.
5. Hash CXEX image excluding signature block.
6. Verify RSA signature.
7. Execute only if verification succeeds.

---

# Public Key Format (.xkpk)

Magic:

```text
CXPK
```

Structure:

```c
typedef struct
{
    char     magic[4];

    uint16_t version;

    uint16_t key_bits;

    uint32_t exponent;

    uint16_t modulus_len;

    uint16_t reserved;

    uint8_t  modulus[];

} XKPK_FILE;
```

# Design Goals

* Small kernel parser
* No ELF dependency at runtime
* Fixed-size header
* Simple section loading
* Built-in code signing
* Future architecture support
* Future relocation support
* Future dependency support
* Easy debugging from a hex editor
